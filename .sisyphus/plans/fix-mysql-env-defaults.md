# Fix: Write MySQL defaults to .env during `canasta create`

## TL;DR

> **Quick Summary**: `podman-compose` doesn't resolve `${VAR:-default}` shell syntax in `docker-compose.yml`, so `MYSQL_HOST=${MYSQL_HOST:-db}` passes through as a literal string. Fix by writing the bundled-DB defaults (`MYSQL_HOST=db`, `MYSQL_PORT=3306`, `MYSQL_USER=root`, `MYSQL_SSL=false`) to `.env` during `canasta create`.
>
> **Deliverables**:
> - Updated `roles/create/tasks/_env_update.yml` — add MySQL defaults to the core .env loop
>
> **Estimated Effort**: Quick
> **Parallel Execution**: NO - single task

---

## Context

### Original Request
`canasta create` creates a web container where `MYSQL_HOST` is set to the literal string `${MYSQL_HOST:-db}` instead of `db`. The web container hangs waiting for a database host that doesn't exist, producing a Varnish 503.

### Root Cause
1. `docker-compose.yml` declares `MYSQL_HOST=${MYSQL_HOST:-db}` — Docker Compose resolves this, but `podman-compose` does not
2. The `.env` file generated by `canasta create` never writes `MYSQL_HOST`, `MYSQL_PORT`, `MYSQL_USER`, or `MYSQL_SSL` for the bundled-DB case
3. The compose file defaults are meant to handle this, but podman-compose passes them through unexpanded

### Research Findings
- `_env_update.yml` (lines 39-56) writes core vars: `MW_SITE_SERVER`, `MW_SITE_FQDN`, `MYSQL_PASSWORD`, `CANASTA_IMAGE`
- `MYSQL_HOST`/`MYSQL_PORT`/`MYSQL_USER`/`MYSQL_SSL` are only written if the user passes an `-e` envfile with `USE_EXTERNAL_DB=true`
- For the bundled DB case (default), these values are never populated — the compose file defaults are the only fallback

  ```yaml
    # Pin the bundled DB defaults so podman-compose (which can't resolve
    # ${VAR:-default} syntax in docker-compose.yml) gets the correct
    # values.  These are only written when the internal DB is used —
    # external-DB setups supply their own via the -e envfile.
    - { key: "MYSQL_HOST", value: "db" }
    - { key: "MYSQL_PORT", value: "3306" }
    - { key: "MYSQL_USER", value: "root" }
    - { key: "MYSQL_SSL", value: "false" }
  ```

  **Why this works**:
  - The `canasta_env` module's `state=set` is idempotent — if the user's `-e` envfile already set these values, they won't be overwritten (the envfile merge runs first in `_envfile.yml`)
  - When `USE_EXTERNAL_DB=true`, the user MUST supply `MYSQL_HOST` (validated by the existing check on lines 83-106), so the default is replaced
  - These values match the `docker-compose.yml` defaults exactly
